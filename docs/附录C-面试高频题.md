# 附录 C CI/CD 面试高频题（40 题带要点）

> 按主题分组。题目来自真实面经常见方向，答案给出"面试官想听到的要点"，深讲见对应章节。

## 基础概念（01/02 章）

**1. CI、CD、CD 三者的区别？**
持续集成：每次提交自动构建+测试；持续交付：随时可发布（人工点按钮）；持续部署：通过验证即自动上线。关键分界在"部署是否自动"。

**2. 构建、制品、环境的定义？**
构建：源码 → 可运行产物；制品：构建结果的不可变封装（镜像/jar/压缩包）；环境：制品运行的位置（dev/staging/prod）。同一制品 + 不同配置 = 不同环境。

**3. 为什么镜像 tag 不能用 latest？**
latest 是可变指针，回滚时 `pull latest` 拉到的还是坏版本。部署必须用不可变 tag（build号+sha）或 digest。

**4. GitFlow / GitHub Flow / trunk-based 怎么选？**
GitHub Flow：简单、持续部署友好；GitFlow：多版本并行维护（发布制软件）；trunk-based：高频小步提交 + feature flag，互联网主流。分支模型决定流水线触发策略。

**5. Conventional Commits 对 CI 的价值？**
commit message 机器可解析 → 自动生成 CHANGELOG、自动打 semver 版本号（major/minor/patch）。

## Jenkins（03~05、17 章）

**6. Declarative 和 Scripted Pipeline 的区别？**
Declarative：结构化（pipeline/stages/post），可读性高，主流；Scripted：Groovy 脚本，灵活但难维护。优先 Declarative，复杂逻辑抽共享库。

**7. Jenkinsfile 为什么必须入库？**
配置即代码：可评审、可回滚、多分支自动生效；否则 Jenkins 界面配置无法版本化，环境漂移不可控。

**8. 凭据管理的最佳实践？**
按用途拆凭据、最小权限、ID 带用途与年份、日志里禁止插值打印、定期清理、凭据文件与 secrets/ 一起备份。

**9. 共享库解决什么问题？什么时候引入？**
多流水线重复逻辑的统一。≥2 处重复先容忍，第 3 处出现再抽 `vars/`。

**10. 为什么 2G 内存的服务器不能跑 Jenkins？**
JVM + Jenkins ≈600MB，加 Docker、系统、业务会 OOM。CI 与生产分离，构建放 CI 机。

**11. Webhook 触发与轮询的取舍？**
Webhook 实时省资源；轮询（SCM polling）简单但延迟大、浪费 API 配额。外网不可达时可用轮询兜底。

**12. Jenkins 升级 SOP？**
备份 jenkins_home + 插件清单 → 一次升一个 → 非发布窗口 → 升级后跑最小流水线 → 失败回退镜像+恢复备份。

**13. Agent 标签隔离怎么保证安全？**
部署 Job 绑专用标签节点；部署凭据限命令白名单；受保护分支才能触发部署 stage。

## 流水线工程（06/16 章）

**14. 三平台（Jenkins/Actions/GitLab CI）最核心的抽象差异？**
Jenkins：中心化服务器+Agent+凭据自管；Actions：托管 Runner+市场 Action；GitLab：.gitlab-ci.yml 单文件+内置 Runner 池。选型看托管位置、内网需求、维护成本。

**15. 缓存 key 设计原则？**
绑 lock 文件内容（变化即失效），不绑 commit（永不命中）或分支名（旧包残留）。npm/pip 缓存下载产物，不缓存 node_modules。

**16. 如何把构建从 10 分钟压到 3 分钟？**
测出耗时分布 → 并行独立 stage → 三类缓存（npm/pip/漏洞库）→ 镜像层缓存 → changeset 跳过无关部分 → 制品传输走内网。

**17. changeset 过滤的风险？**
部署相关文件（Dockerfile/deploy脚本/compose）变动必须全量跑；分支首次构建无基线需全量。

## 构建与镜像（07/08/10 章）

**18. npm ci 与 npm install 的区别？**
ci 严格按 lock 装且先删 node_modules，可复现且快；install 会解析范围更新。CI 只用 ci。

**19. Dockerfile 多阶段构建的意义？**
编译工具链与运行时分离，最终镜像不含编译器与缓存；依赖层（COPY requirements→install）与代码层分离提升缓存命中。

**20. 镜像 Tag 策略？**
构建 tag `build号-sha` 不可变；语义版本 tag 与 Git Tag 对应；latest 仅作参考不用于部署；回滚依赖历史 tag + digest。

**21. 镜像瘦身三板斧？**
多阶段构建、slim/alpine 基础镜像、依赖安装加 --no-cache-dir/--omit=dev 并清理缓存；.dockerignore 缩上下文。

**22. 2M 带宽下如何部署？**
服务器只拉镜像不构建；镜像从同云同地域仓库走内网拉取（不计公网带宽）；前端 gzip + 强缓存。

## 质量与安全（09 章）

**23. 覆盖率阈值怎么定？**
基线法：当前值-2% 起步，逐迭代 +2% 至 80% 左右；对新增代码要求更严。警惕 100% 覆盖的假断言。

**24. 依赖漏洞扫描的阻断策略？**
只拦 HIGH/CRITICAL 且有修复方案的（--ignore-unfixed / --audit-level=high），低危周期性审查；豁免必须记录原因与复查日期。

**25. 密钥扫描为什么加 --redact？**
扫描工具会把命中内容打进 CI 日志，日志可见范围更宽，会变成新的泄露渠道。

**26. 门禁太严导致开发者绕过怎么办？**
显式参数+审批+日志留痕的例外流程，而不是删门禁；复盘例外原因，能自动化修复的自动化。

## 部署（11~15 章）

**27. 蓝绿 / 滚动 / 金丝雀的区别与适用？**
蓝绿：双环境全量切换，回滚快但资源×2；滚动：逐实例替换，资源省但窗口期两版本并存；金丝雀：小流量验证再放量，需流量控制。单机常用蓝绿思想（备用端口+切流量）。

**28. releases + current 软链接方案的回滚原理？**
每版本一个自包含目录（compose+env），current 软链指向当前；回滚=ln -sfn 切软链 + compose up -d，秒级。

**29. 为什么 deploy.sh 先 pull 再切软链？**
拉取可能失败；先切链后拉取会让 current 指向镜像不存在的版本，旧容器已被移除则服务中断。

**30. 健康检查为什么不能查数据库？**
健康检查决定流量是否切给实例；数据库抖动会让所有实例同时被判死，流量全摘，故障放大。进程活性与依赖健康要分开。

**31. 优雅退出的两个配置点？**
应用层监听 SIGTERM 并处理（uvicorn --timeout-graceful-shutdown）；编排层 stop_grace_period 要大于应用退出时间，否则被 SIGKILL。

**32. HTTPS 无域名怎么解决？**
自签 CA（SAN 必须含 IP）+ 导入信任；进阶用 sslip.io 拿 Let's Encrypt 真证书；买域名后只改证书、server_name、API baseURL 三处。

**33. X-Forwarded-Proto 不传会怎样？**
后端以为自己是 HTTP，生成 http:// 链接 → HTTPS 页面请求 HTTP 资源 → 混合内容被浏览器拦截。

**34. proxy_pass 末尾带不带 / 的区别？**
带 URI（如 /api/）会把 location 前缀替换掉导致路径二次拼接；不带则原样透传。最常见 404/路径错原因。

## 配置与数据（14 章）

**35. .env 的三层纪律？**
权限 600、绝不入库、仓库只有 .env.example 模板。已泄露要换密钥（Git 历史删不掉）。

**36. SQLite 备份为什么不能用 cp？**
WAL 模式下最新提交可能在 -wal 文件里；cp 主文件丢数据。用 .backup 命令或 Python backup API 拿一致性快照，且备份必须解压校验。

**37. 数据库迁移如何保证回滚安全？**
扩展-收缩模式：加列设默认值可空、旧代码显式字段查询不感知新列、稳定后才能清理旧列。任何发版前确认上一版代码能在新库上启动。

## 治理与演进（17~20 章）

**38. DORA 四项指标？**
部署频率、变更前置时间（commit→上线）、变更失败率（回滚/部署）、恢复时长。采集靠部署台账，价值看趋势不看绝对值。

**39. 推模式与拉模式（GitOps）的差异？**
推：CI 主动部署，服务器被动接受；拉：Git 声明期望状态，集群组件持续比对纠偏。拉模式消除配置漂移、状态可审计，代价是多一套常驻组件与"操作必须走 Git"的纪律。

**40. 单机到集群的演进信号？**
资源长期 >70%、高可用刚需、服务 >10 个、自动扩缩需求、多团队抢发布窗口。先做便宜演进（加机器/分机/CDN），SQLite→PostgreSQL 是多副本的前置改造。
